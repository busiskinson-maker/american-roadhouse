# Antislop Audit 003

Date: 2026-10-21  
Scope: Static review of mobile navigation, menu tabs, and fixed actions.

## Findings

### 1. [HIGH] Menu tabs have no narrow-screen layout (R-03)

The menu page has five category tabs, but `.tabs` remains one unwrapped flex row and each `.tab-btn` adds a 26px right margin. On phone widths, labels and tap areas have little room. Let the tabs wrap or provide a clearly scrollable tab row with comfortable targets. Evidence: `menu.html:97-102`, `assets/css/style.css:617-622`.

### 2. [HIGH] The fixed mobile action bar ignores the device safe area (R-03)

`#mobile-bottom-bar` is fixed at `bottom: 0` and `body` reserves a fixed 62px, with no safe-area inset. On phones with a home indicator, the bar can sit too close to the system gesture area. Add safe-area padding and reserve the matching space. Evidence: `assets/css/style.css:240-262`.

### 3. [HIGH] The mobile menu control is small and visually unlabeled (R-03)

The menu button contains a 26px icon with 6px padding, giving it a 38px target, below the skill’s 44px touch-target guideline. Its “Open menu” name is available to assistive technology, but there is no visible “Menu” label. Enlarge the target and make the control’s purpose visible. Evidence: `index.html:57-59`, `assets/css/style.css:200-204`.

### 4. [HIGH] The mobile menu cannot be dismissed with Escape (R-32)

The menu opens and closes through click handlers, but the shared script has no Escape handler for the menu and does not return focus to its opener on close. Add keyboard dismissal and focus restoration. Evidence: `assets/js/main.js:13-18`.

## Existing responsive work

The site already collapses the main grids, reduces section spacing below 768px, and switches the menu-board grid from three columns to two and then one. These rules are in `assets/css/style.css`.
